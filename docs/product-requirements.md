# Cockpit 定位与验收准则

本文记录已明确的产品要求和已接受取舍，编号可供设计、审阅与验收引用。
它不是当前实现清单、发布记录或新增功能授权。实现说明见
[底座设计](cockpit-plan.md)，接口细节见[原生聊天](native-chat.md)与
[MCP](../apps/mcp/README.md)。建议只有经明确确认后才能成为要求；不能将现有实现反写成产品决定。

## R1 · 薄底座，扩展保持边界

Cockpit 是原生 agent/session 能力的薄接入与交互底座，不是第二套 Copilot
或任务调度平台。保留 TypeScript、HTTP POST 和 SSE；Web、API、MCP 共用明确契约。

Work Commander 独立管理工作目标、授权、进展和结果；微信是渠道连接器，大屏是展示模式。
接受 Commander 依赖 Cockpit，不要求现在通用适配其他底座。统一理解扩展，不等于同进程、
共享数据库或立即建设插件框架；任务语义不进入基础 MCP。

## R2 · 原生状态只有一个权威

后端不保存原生聊天或会话状态的长短期副本，不后台同步、遍历私库或用缓存兜底。
请求内结果及局部索引用完释放；SDK 自有内部缓存与 Cockpit 自建副本须分清。

允许真实必要、按生命周期释放的控制回调、连接和在途资源；前端可持当前展示窗口。
托管文件、置顶和通知必要信息属于 Cockpit 产品数据，可保留。
不能以极简之名删除业务权威、持久化保护或交付凭据，也不能靠改名规避副本约束。

## R3 · 忠实使用 SDK 契约

按安装版本的公开契约核对每类实际能力的调用、适配及消费者；原生能直接完成的，
不在上层绕路重造。不要求接入每个 SDK 函数。

保留 MCP 连接/认证/停止状态、调度类型、模型 effort/context tier 和排队语义。
字段缺失、不支持和未知值分别表达，不硬编码模型档位或猜默认，不将 queued/受理等同生效。
不因后续无关读取失败而把已经成功的变更误报失败。

错误明确返回，不静默换读 home、混源补救、吞异常或伪造成功。
原生缺能力时明确说明；重要体验替代先与用户商量。

## R4 · 只读、只算消费者真正需要的内容

避免为列表或单字段读取整套面板、无关失效引发全量刷新、重复请求和重复全窗口计算。
可复用请求内结果与局部索引，不恢复跨请求原生副本。

按完整用户动作或完整重连累计成本，不按批重置预算，不靠增大页或把 event 当 message 粉饰。
分开报告 HTTP/MCP 往返、SDK 调用、可证实 RPC、事件/字节及 CPU 重复处理；
不能混称 token、磁盘 I/O 或现网延迟。SDK 只有 list 时，必要 list 不自动构成缺陷。
优化须减少真实成本，而非只缩短文字或代码。

## R5 · 历史、实时与断线恢复一致

主/子 agent 自建立读取起统一 all 范围，共用前端阅读窗口及原生 cursor。
子视图收起也持续更新，展开不另读、不要求刷新。SSE 推实际内容，不推失效后再重拉累计窗口。

普通重连沿同范围有效 cursor 增量补 durable 消息、工具和生命周期，及时展示已补到的完整消息。
保留事件去重、真实归属、完整消息替换 partial 和 bootstrap 竞态保护。
expired/rewind 明确重同步，不暗中全历史兜底。

不承诺临时 delta 逐 token 无损重放、未完成文本前缀可恢复或 cursor 永久有效。
取消读取不能中断主模型。

## R6 · 自然交互，产品取舍明确

普通会话列表保留置顶，不恢复项目/worktree 分组。自然布局、单一滚动控制；
重入最新落底，上翻不强跳。按消息而非整轮加载，保留完整消息、至少两屏自动填充、
近顶预取与明确加载态。

保留首次自动命名和手动标题保护；菜单命名入口退役，API/MCP 原生命名能力保留。
不恢复空会话自动重建、旧草稿通道、退役偏好或回收站；当前 Composer 草稿/附件不在删除范围。

原生工具历史图片查找退役，使用显式上传的本地原件或托管文件。
托管文件长期保留，不随会话删除或自动到期；`/uploads` 不是匿名公开链接。
不借审阅撤销功能、重写全局请求机制或进行全面手机/性能改造；重要交互取舍先确认。

## R7 · 安全和生命周期如实表达

保留用户确认、权限/配置来源、fork 历史前检、活动工作/队列保护、晚结果隔离、背压和释放。
永久删除走原生 API，明确不可恢复并要求确认；不无确认升级旧客户端语义，
不删除独立托管文件或工作区。

未知副作用不自动重放，不擅自换 owner 或重发消息。mode 不是 permission；
enabled 不是 connected；pin 不是保活；进程 idle 不是工作完成。

如实说明单用户本机信任边界及独立 Passkey 认证层，不宣传可强隔离所有同用户 agent。
公开页面、API 和文件的权限要求不能被展示功能绕开。

## R8 · 文档、版本和交付可追溯

文档与 MCP 说明对应真实能力，不保留退役 locator、保活或旧重试等误导。
区分需求、建议、当前实现和历史状态；分别报告开发、提交、集成、部署及运行生效。
health 成功不是 SHA 证明，源码完成不是线上完成。

必要时独立 worktree，安全集成并保留他人成果；不强停忙会话，不从未整理脏树盲目发布。
长期方向是 main 后固定 SHA 构建、安全不可变包发布。
当前 source/systemd 完整功能版先上线属于已接受过渡，不等于已经完成 CI/CD 迁移。

## 已接受成本、延期及未定事项

| 类别 | 边界 |
| --- | --- |
| 已接受 | 完整消息/归属/两屏可额外读取事件；低可见密度极端暂不考虑，不恢复硬停来假装严格一页预算。 |
| 已接受 | 不逐页 ACK；极端断网或慢消费者少量尾部重读可接受，不承诺严格一页未确认上限。 |
| 已接受 | 单个巨型 event 允许整读后按 offset/hash 分片；普通多 event 超限显式缩页，不自动二分、缓存、转存或增加 opt-in。 |
| 已接受 | 收起子 agent 仍传输是持续更新的体验成本，不按旧 primary 方案判作无消费者浪费。 |
| 已延期 | 音频晚启动与 token 生命周期问题留待后续，不自动实施或再次要求设备操作。 |
| 已暂停 | 微信未知发送不恢复、不重发；压缩超时/空响应需根因证据，不能直接归为 Cockpit 误用。 |
| 尚未决定 | 单层串行子 commander 试点不等于正式纳入 Work Commander，更不授权任意递归。 |
| 非本准则的实施授权 | CI/CD 迁移、大屏语音、通用插件框架和开源发布须按各自明确授权推进。 |

上述取舍已修订早期绝对单消息/单页冗余目标，不能在验收时悄悄恢复旧门槛。
符合性审阅应逐项标注**符合、部分符合、不符合、已接受例外或未知**，给出实际基线、
证据与未覆盖边界；源码推导、合成测试、真实 SDK 实证和线上事实不能相互冒充。
