# Cockpit 定位与验收准则

本文记录已明确的产品要求和已接受取舍，编号可供设计、审阅与验收引用。
它不是当前实现清单、发布记录或新增功能授权。实现说明见
[架构与运行边界](cockpit-plan.md)，接口细节见[原生聊天](native-chat.md)与
[MCP](../apps/mcp/README.md)。建议只有经明确确认后才能成为要求；不能将现有实现反写成产品决定。
各主题的唯一维护位置见[文档索引](README.md)，实际发布状态见[部署记录](deployments.md)。

## R1 · 薄底座，扩展保持边界

Cockpit 是原生 agent/session 能力的薄接入与交互底座，不是第二套 Copilot
或任务调度平台。保留 TypeScript、HTTP POST 和 SSE；Web、API、MCP 共用明确契约。

2026-09-12 的明确决定替代此前的官方模块宿主范围：先清理 Cockpit 本体，
停用并移除旧模块加载功能，只保留[基础模块协议设计](module-contract-draft.md)；
以后再逐个模块完善、适配并演进协议，不在本轮实现大型通用插件框架。

Assistant 内容、Task/Commander 业务、渠道协议及其身份签发、绑定、配置、服务、
网关和页面不属于本体。本体没有官方模块 ID 白名单、固定业务角色或专用业务分支。
Copilot 原生的 `assistant` 消息角色/事件与 `task` 子代理工具属于原生能力，
正常保留；它们不是这些业务模块。Web 仍属于本体。
清除源码接入不等于删除既有模块数据、凭据、已安装程序文件或原生会话。

进一步确认的范围见[完整模块目录](module-catalog.md)：文件、通知/收件箱、
语音、会话整理、系统看板、Graceful Restart 和 Context Reset 的增强工作流也迁出。
实施顺序为先按能力保全原始代码、测试、文档和资源，再从运行路径摘除；不立即适配模块。
前端同样是插件，通过有版本的公开 UI 组合契约协作，不预埋文件或语音专用槽位。
聊天流中的文件卡片、媒体预览和下载展示也归文件插件。

### 2026-09-13 晚间确认的下一版边界

以下是 19:34–20:49 讨论收敛后的**目标**，替代此前把安装/部署运行器留作本体组成、
模块独立服务进程及首版热加载的设想。主程序运维外围现已从源码移出，
但新的模块宿主尚未实现；完成状态与运行事实以[架构](cockpit-plan.md)为准。

| 已确认目标 | 边界 |
| --- | --- |
| 一个前后端服务包 | 包含后端入口、built Web 和必要运行依赖；直接启动即可统一 serve，不先启动或询问 Cockpit 自带的部署控制器。 |
| 不内置主程序运维系统 | runner、私有 launch、循环重拉的 start wrapper、consumer 自更新、部署审批/回执、版本切换和回滚编排不属于本体运行包或启动依赖。普通构建、测试、产包 CI 可以保留。 |
| 模块同进程 import | 模块后端由本体加载，前后端作为一个模块包交付并由宿主统一提供；无模块自有守护进程、MCP 子服务进程或自治启停系统。独立仓库、版本和业务数据可以保留。 |
| 首版冷加载 | 不做热插拔或运行中代码替换。安装、代码更新、停用/移除的变更记录为待重启生效，当前实际加载版本不变；下次本体启动加载选定版本。 |
| MCP 分入口 | 同一端口下按模块 path 提供独立 MCP 工具/资源/prompt 集合和协议连接；不是所有 path 指向同一个大工具表。 |
| 本体只负责 graceful 退出 | 等待已接纳的原生工作与宿主在途操作收敛，正常释放资源后退出；不判断业务目标完成，不保证重新拉起。 |
| 可选的下次启动消息 | 模块可通过自己的 MCP 保存一次性接续 prompt，下一次宿主就绪后发给指定原生 session；不是本体隐式欢迎消息、部署回执或原生状态镜像。 |

“一个服务进程”不排除 SDK 自身的进程外 Copilot runtime、原生 MCP/工具子进程，
也不把浏览器前端视为宿主 OS 进程。模块没有独立运行权威，但仍需由宿主统一初始化、
跟踪请求和释放资源；同进程不提供内存、崩溃或恶意代码隔离。
“一个包”也不表示任意宿主零前提可运行；平台、Node 和原生依赖要求需明确，
是否将 Node 可执行文件合包尚未在本次决议中确定。
MCP path 是协议/工具命名空间，不是新的权限系统；现有认证与用户选择仍适用。
原生 session 的 MCP 开关不是模块代码热加载，继续遵循原生配置语义。

细节由[模块协议](module-contract-draft.md)维护；当前差距及迁出位置见
[架构对照](cockpit-plan.md#target-gap)和[待迁出盘点](module-catalog.md#pending-extraction)。

## R2 · 原生状态只有一个权威

后端不保存原生聊天或会话状态的长短期副本，不后台同步、遍历私库或用缓存兜底。
请求内结果及局部索引用完释放；SDK 自有内部缓存与 Cockpit 自建副本须分清。

允许真实必要、按生命周期释放的控制回调、连接和在途资源；前端可持当前展示窗口。
文字草稿和当前展示窗口属于前端交互状态，不是后端原生镜像。托管文件、置顶和通知信息
属于相应模块，不是本体持有原生状态副本的例外。
模块角色内容、业务身份和业务记录属于模块。当前本体没有模块加载器；
未来宿主只保留安装选择、实际 import 引用、通用注册和所拥有资源等必要加载元数据，
不借此保存原生状态副本。旧业务记录保留为未接管数据，不自动恢复、注入或重放。
不能以极简之名删除已有业务数据或交付凭据，
也不能靠改名规避原生副本约束。

## R3 · 忠实使用 SDK 契约

按安装版本的公开契约核对每类实际能力的调用、适配及消费者；原生能直接完成的，
不在上层绕路重造。不要求接入每个 SDK 函数。

保留 MCP 连接/认证/停止状态、调度类型、模型 effort/context tier 和排队语义。
字段缺失、不支持和未知值分别表达，不硬编码模型档位或猜默认，不将 queued/受理等同生效。
不因后续无关读取失败而把已经成功的变更误报失败。

Web、MCP 和其他 API 消费者使用同一套原生创建和发送语义：
`session/new(cwd) → 真实原生 ID → prompt`。创建不隐式发送初始化消息，
不以虚拟 session、预留聊天地址或首消息专用生命周期代替原生对象。
MCP 直接对应 API，参数名转换和展示格式不改变业务语义、条件或副作用。
目录选择只是未提交表单；空原生会话卸载后可能消失，不自动重建。
旧 `modules` 创建参数明确拒绝，不忽略后假报角色接入成功。

错误明确返回，不静默换读 home、混源补救、吞异常或伪造成功。
原生缺能力时明确说明；重要体验替代先与用户商量。

## R4 · 只读、只算消费者真正需要的内容

避免为列表或单字段读取整套面板、无关失效引发全量刷新、重复请求和重复全窗口计算。
可复用请求内结果与局部索引，不恢复跨请求原生副本。

按完整用户动作或完整重连累计成本，不按批重置预算，不靠增大页或把 event 当 message 粉饰。
分开报告 HTTP/MCP 往返、SDK 调用、可证实 RPC、事件/字节及 CPU 重复处理；
不能混称 token、磁盘 I/O 或现网延迟。SDK 只有 list 时，必要 list 不自动构成缺陷。
优化须减少真实成本，而非只缩短文字或代码。

## R5 · 历史、实时与断线恢复一致

主/子 agent 自建立读取起统一 all 范围，共用前端阅读窗口及原生 cursor。
子视图收起也持续更新，展开不另读、不要求刷新。SSE 推实际内容，不推失效后再重拉累计窗口。

普通重连沿同范围有效 cursor 增量补 durable 消息、工具和生命周期，及时展示已补到的完整消息。
保留事件去重、真实归属、完整消息替换 partial 和 bootstrap 竞态保护。
expired/rewind 明确重同步，不暗中全历史兜底。

不承诺临时 delta 逐 token 无损重放、未完成文本前缀可恢复或 cursor 永久有效。
取消读取不能中断主模型。

## R6 · 自然交互，产品取舍明确

普通会话列表按原生活动排序，置顶归会话整理模块，不恢复项目/worktree 分组。自然布局、单一滚动控制；
重入最新落底，上翻不强跳。按消息而非整轮加载，保留完整消息、至少两屏自动填充、
近顶预取与明确加载态。

首次回复自动命名策略归会话整理模块；原生手动命名和标题读取保留，不另建标题副本。
不恢复空会话自动重建、退役偏好或回收站。本体只提供普通文字输入；
旧富草稿保留但不自动继承、覆盖或迁移，后续模块另行设计采用路径。

HTTP/MCP 可以忠实传递 SDK 原生 `file/directory/selection/blob` 附件参数，
但不提供浏览器上传下载、托管文件库、模块引用解析或文件渲染。
文件路径属于 Copilot 运行侧，不能冒充浏览器或另一台机器的本地路径。
原生工具历史图片查找不恢复。既有托管文件不随源码提取或会话删除而清理；
停用文件服务不等于数据删除，也不能承诺旧链接在没有模块时仍可下载。
不借审阅撤销功能、重写全局请求机制或进行全面手机/性能改造；重要交互取舍先确认。

## R7 · 安全和生命周期如实表达

保留用户确认、权限/配置来源、fork 历史前检、活动工作/队列保护、晚结果隔离、背压和释放。
永久删除走原生 API，明确不可恢复并要求确认；不无确认升级旧客户端语义，
不删除独立托管文件或工作区。
删除不以模块解绑、预览计划、额外审批或回调成功为前置，也不广播给模块。
外部应用在使用 ID 时自行处理失效引用；unloaded、超时和权限错误不是删除。
原生会话删除不依赖模块业务回调。未来同进程模块的通用资源由宿主统一关闭，
但本体不接管其目标判断、渠道补发或业务恢复。

正常关闭只提供 graceful 语义：等待原生活动工作、已接纳队列、用户决策、附着资源
和宿主在途操作收敛，再正常关闭空闲 handle、模块资源、SDK 和网络连接。
不是等待所有已保存 session 从列表消失，也不等待未来未到期的 schedule 永远保持空闲。
关闭阶段应收口新独立工作，同时保留已有问答/在途操作完成所需通路；不能清空队列、
抹掉 busy 或在安全状态未知时假报完成。
发起关闭的 MCP/API 请求返回受理后，原生调用回合必须能结束，不能等自己退出。
退出入口使用同一可发现的公开 API 和既有认证，区分受理/等待与完成。
当前 `system/shutdown` / `system/status` 的精确契约见[关闭说明](cockpit-plan.md#shutdown)，
不保留旧私有部署分支作为别名。

此前讨论的“本体普通立即退出、模块负责等待空闲”不采用；graceful 控制留在本体，
不依赖可卸载模块。本体不自重启，启动者是否再次拉起由外部环境或人工决定。
已确认原生进程死亡时的错误退出仍属故障处理，不是正常关闭绕过安全保护的入口。
Context Reset 的 self-only 工具/skill 仍归模块，不混同关闭本体。
能力拆分或文档更新不自动授权重启、reset、模块启用或生产数据迁移；实际操作需另有授权。

未知副作用不自动重放，不擅自换 owner 或重发消息。mode 不是 permission；
enabled 不是 connected；UI 标记不是保活；进程 idle 不是工作完成。

如实说明单用户本机信任边界及独立外部认证层，不宣传可强隔离所有同用户 agent。
当前部署的 Passkey 网关不是本体账号系统；Origin/Referer 检查不是身份认证。
Copilot 登录仍归原生运行时。新源码不依赖自有 launcher；已记录生产安装的外部启动链
并未因此被替换，事实见[部署记录](deployments.md)。源码提取不得未经授权破坏现有运行方式。
公开页面、API 和文件的权限要求不能被展示功能绕开。

## R8 · 文档、版本和交付可追溯

文档与 MCP 说明对应真实能力，不保留退役 locator、保活或旧重试等误导。
区分需求、建议、当前实现和历史状态；分别报告开发、提交、集成、部署及运行生效。
health 成功不是 SHA 证明，源码完成不是线上完成。

必要时独立 worktree，安全集成并保留他人成果；不强停忙会话，不从未整理脏树盲目发布。
保留可追溯的源码、构建和包身份；目标的产包职责不包含私有生产部署权威。
原交付/更新流程已[移到项目外](extractions.md)，本体只保留[普通产包](packaging.md)。
部署事实只记在[部署记录](deployments.md)；文档目标变更不自动停用现行 CI/CD、
重启主机服务、移动用户数据或使既有部署记录失效。

## 已接受成本、延期及未定事项

| 类别 | 边界 |
| --- | --- |
| 已接受 | 完整消息/归属/两屏可额外读取事件；低可见密度极端暂不考虑，不恢复硬停来假装严格一页预算。 |
| 已接受 | 不逐页 ACK；极端断网或慢消费者少量尾部重读可接受，不承诺严格一页未确认上限。 |
| 已接受 | 单个巨型 event 允许整读后按 offset/hash 分片；普通多 event 超限显式缩页，不自动二分、缓存、转存或增加 opt-in。 |
| 已接受 | 收起子 agent 仍传输是持续更新的体验成本，不按旧 primary 方案判作无消费者浪费。 |
| 已迁出 | 语音及其晚启动/token 生命周期缺口留在原始归档中，后续模块适配时处理，不声称已修复或可用。 |
| 不属本体 | 模块业务及渠道的未知副作用由原业务方按证据处理，不自动恢复、重发或接管。 |
| 非本准则的实施授权 | 部署、语音适配、通用插件框架和开源发布须按各自明确授权推进；已有交付流程不等于自动部署许可。 |
| 已确认 | 旧模块协议、专用路由和配置不兼容；当前移除加载功能，后续模块接入单独实施。数据不随接口退役删除。 |
| 已确认 | 首版不做模块热加载；同进程 import、冷启动应用版本和独立 MCP path 是新目标，不是当前已上线功能。 |
| 已接受边界 | 下次启动消息只承诺明确记录自动发送尝试与结果；当前 prompt 无接收端幂等键，不能仅靠本地标记保证崩溃下不漏不重。 |

上述取舍已修订早期绝对单消息/单页冗余目标，不能在验收时悄悄恢复旧门槛。
符合性审阅应逐项标注**符合、部分符合、不符合、已接受例外或未知**，给出实际基线、
证据与未覆盖边界；源码推导、合成测试、真实 SDK 实证和线上事实不能相互冒充。
