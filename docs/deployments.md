本文只记录**有明确授权、来源证据及实际运行回读的部署**，不是持续实时状态、
待发布清单或自动部署授权。普通包的来源通过构建产物和 manifest 核对，

这些证据属于不同安装方式，不能要求直接服务继续依赖已迁出的控制器。

实际 `POST /intent/system/shutdown {"confirm":true}` 只调用一次，先返回 `waiting`；
当时 `busy:1` 是发起操作的原生回合。回合结束后，服务以退出码 **0** 结束，

所以“确实停止”和“随后恢复”不是通过猜测实例 ID 得出的。

按用户选择，独立主机观察程序确认上述结果后移除临时覆盖，恢复宿主已有的
`Restart=always`，并显式启动同一包。恢复后的新实例和 `/health` 一致，
实际 Web index/入口资源匹配 manifest，关闭状态回到 `running`。
本体没有自行启动自己。一次性观察进程已结束，临时覆盖已移除。

匿名公网入口仍要求认证；没有复制、迁移或删除原生会话/用户数据，没有启用业务模块。
旧运行包和外部交付控制器保留，但后者不再是当前主服务的启动权威。
这里验证了一个真实发起回合的等待、正常退出与主机恢复，不宣称覆盖所有故障场景
或已经实现通用的启动消息模块。
