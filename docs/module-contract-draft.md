# 基础模块协议：设计基线

> **当前源码没有模块加载器。本文是后续接入的基础约定，不是已实现 API。**
> 2026-09-12 的决定是先清理 Cockpit，之后逐个完善模块、实现通用接入并演进协议。
> 不再同时实现所有模块、完整插件平台或旧协议兼容层。
> 2026-09-13 已确认前后端插件、无预置专用槽位的界面组合，以及文件的聊天流展示归文件插件。
> 本文记录后续模块接入设计；源码停放范围另见模块清单，不代表模块启用或生产部署。
> 产品范围以 [R1–R8](product-requirements.md) 为准。

完整能力归属、本体保留项和当前“先停放源码、不适配模块”的执行范围见
[模块清单](module-catalog.md)。用户已要求一并安排 Graceful Restart 和
Context Reset；原生安全退出和底层上下文 API 不因增强入口迁出而被破坏。

## 1. 当前边界

Cockpit 是好用的 Copilot 代理：原生会话、消息、模型、MCP、skill、队列、
计划、子代理和调度由 SDK 唯一负责；Web/MCP 共用产品 API。
较早的 `c934978` 基线仍内置托管文件、通知和语音。本轮薄本体源码已将这些
增强从运行路径摘除，原件放入 `module-staging/`，但没有把它们适配为模块。
这不代表现有生产实例已经部署本轮源码。
认证边界、必要的交互状态和本体安全退出仍需保留。

本体已移除旧模块注册、安装、配置、服务运行器、会话角色接入、业务网关和模块 UI。
没有预置业务模块 ID、固定业务角色、身份签发或渠道绑定流程。
`session/new` 只接受 `{ "cwd": "..." }`；旧 `modules` 参数被拒绝。
`modules/*`、`session/modules/*` 和旧专用模块 HTTP 路径不再是可用能力。
本体启动、原生会话冷加载和主程序重启不再读取模块记录来恢复角色、业务进程或任务。
源码清理不会抹掉原生历史或已进入模型上下文的旧文字。

Copilot 原生的 `assistant` 消息角色/事件、`task` 子代理工具以及 native
tasks/todos 并不是业务模块，正常保留。原生配置发现及用户自己的 MCP/skill
管理也保留；移除本体模块加载器不授权改写用户的原生全局配置或工作区文件。

源码退役不删除既有安装目录、配置、凭据、业务记录、附件和原生会话。
旧模块协议、专用路由、配置及 driver 不兼容；旧记录既不自动迁移，也不自动重放。
仓库集成不等于部署，更不意味着任何已有运行实例自动切换。

## 2. 什么才是模块

模块是**有稳定身份、独立版本、明确能力和独立责任边界的完整能力单元**。
它拥有自身需要的配置、私有数据、凭据和运行资源，可以单独安装、启停、
升级或卸载；不需要这些资源时不必伪造空服务或空数据库。

判断标准是能力和生命周期能否独立负责，而不是文件、按钮、进程或提示词数量。
纯角色/skill 内容包可以是模块；一个必须和本体原子维护的原生适配函数不是模块。
模块可以有服务、没有页面，也可以只有声明式内容。模块不能接管原生
session 身份、历史、模型上下文、队列或调度权威。

| 必选约定 | 含义 |
| --- | --- |
| 身份、版本和协议版本 | `moduleId` 是稳定字符串，不是宿主枚举；显示名不是身份或发布者证明。 |
| 声明式能力清单 | 安装前可静态读取；至少声明一个支持的能力，不执行代码来猜能力。 |
| 宿主/原生/平台兼容条件 | 不适用的条件可以不声明；不能把未知兼容性当兼容。 |
| 程序与状态分离 | 已安装版本不可变；配置、业务数据和秘密不写入程序目录。 |
| 信任和生命周期结果 | 未验证不执行；受理、完成、失败、未知及原操作身份明确区分。 |

| 可选能力 | 基础边界 | 后续实现要求 |
| --- | --- | --- |
| 角色说明、skill | 包内相对路径；按显式选择使用，不覆盖工作区规则，不隐藏发送初始化消息。 | 使用原生适配，不存原生开关副本；后续读取正文及引用来自一致版本。 |
| MCP / 原生工具接入 | 声明名称、入口和作用域；冲突拒绝，不以覆盖同名能力解决。 | 采用 SDK 支持的接入方式；现有连接换代需显式确认，磁盘更新不等于连接更新。 |
| 独立服务 | 服务可选；健康、实际身份、排空、退出由拥有它的运行器负责。 | 一个明确运行归属，不抢外部进程，不把本体自更新等待变成等自己退出的死锁。 |
| 命名空间 API / 事件 | 模块自行定义输入、输出和业务副作用；不把业务路由写进宿主。 | 通用注册/调用协议实现后才可声明支持；Web/MCP 使用同一能力定义。 |
| 页面 | 模块自己的页面和业务控制；不要求所有模块有页面。 | 宿主只提供明确通用入口及必要安全边界，不内置业务页面或逐模块菜单分支。 |
| 前端插件 / 界面组合 | 独立编译的可信前端包可贡献控件、页面和展示，不限于独立菜单页。 | 依赖公开组件与交互契约；不预置文件/语音槽位，不通过私有 DOM/CSS 选择器或内部 store 注入。 |
| 配置 / 初始化 / 会话应用 | 配置 schema、版本和秘密引用由模块定义；业务身份及唯一绑定由模块签发/判断。 | 通用可选生命周期调用；没有该能力就不调用，不制造空成功回执。 |

以上是待实现能力类别，不是当前完整的可执行 wire schema。首个需要某种能力的
模块接入时，应连同通用宿主实现、同语义 Web/MCP 入口和隔离用例一起定义其精确版本。
不能因为表中列了“页面”或“服务”，就宣称任意现有模块已经无改动可用。
首版不加自动依赖安装、跨模块数据库、循环依赖或任意远程安装脚本。

### 2.1 已确认的下一版职责划分

模块可以同时提供前端和后端，并共同构成统一 App；不强制纯前端或内容模块
启动无用服务。本体的业务能力限于原生 Copilot 适配和展示，另外仅保留远程代理、
认证、模块信任/加载、界面组合及最小恢复所需的通用基础设施。
这些宿主基础设施不是 Copilot 原生业务能力，不应混称原样透传。

| 模块 | 完整责任范围 | 不接管的原生/宿主责任 |
| --- | --- | --- |
| 文件 | 上传、托管、元数据、下载、文件库；输入框的选择/粘贴/拖拽、暂存和进度；聊天流中的附件卡片、图片/视频预览、下载入口及模块文件引用解析。 | 不接管原生会话、消息历史、cursor、队列和发送权威；本体不留下文件专用渲染器或另造托管附件格式。 |
| 通知 / 收件箱 | 未读/已读记录、提醒规则与去重、通知订阅、Web Push、收件箱和会话列表提示。 | 这里的“消息”是消息提醒，不是原生消息收发/历史。真实 ask/plan 及其响应仍由原生适配负责。 |
| 语音 | 浏览器采音、识别、语言配置、识别状态、服务密钥/令牌以及相关控件。 | 听写结果通过通用文本编辑接口进入原草稿，不接管发送；只有发送录音文件的可选功能才需要文件能力。 |

停用文件插件意味着浏览器文件上传、模块下载和专用预览不可用，不意味着
Copilot 失去操作其运行环境文件的能力，也不意味着删除已有文件或原生附件记录。
不为维持增强功能而由本体暗中接管模块业务。

## 3. 最小声明示例（合成，不能直接安装）

```json
{
  "schemaVersion": 2,
  "kind": "cockpit.module",
  "moduleId": "org.example.notes",
  "version": "1.0.0",
  "name": "Notes",
  "requires": {
    "hostProtocol": 2,
    "nativeFeatures": ["session-mcp"]
  },
  "capabilities": {
    "roles": [{
      "id": "reader",
      "instructions": "roles/reader.md",
      "skills": ["skills/notes"]
    }]
  }
}
```

`schemaVersion` 属于这个带 `kind` 的新格式，不兼容旧官方模块 manifest。
`moduleId` 建议反域名命名；重复 ID 不能靠不同显示名混装，版本绑定还必须包含
已验证内容摘要。能力条目和角色 ID 由模块提供，宿主没有官方名称分支。
所有包内路径必须限制在包内的普通文件/目录；入口不是 shell 命令字符串。
上例不需要服务、页面、初始化、配置或本体专用处理。

如果模块包含可执行服务，还必须声明平台、架构、运行时要求和精确入口；
若需要配置，另声明配置 schema/版本及秘密引用。不能从 manifest 缺失字段
推导“在任何宿主都能运行”，也不要求纯内容包安装 Node 或启动空进程。

## 4. URL 入口与信任

推荐只支持一种首版入口：**HTTPS 签名发行描述 URL**。
发行描述绑定协议版本、模块 ID/版本、manifest、产物 URL、大小、SHA-256、
有效期及发行序列；Ed25519 签名覆盖明确编码的完整 payload 字节。
发布者公钥必须来自独立可信配置或用户对新来源的明确确认。

```json
{
  "payload": "<base64 of the complete release JSON bytes>",
  "signature": "<base64 Ed25519 signature>"
}
```

普通仓库/Release HTML、裸 ZIP、裸未签名 manifest 不猜测为可运行模块。
未来可以增加明确的来源适配，但不是在 HTML 中搜任意链接然后执行。
目录可以给推荐来源，不能成为模块 ID、仓库或域名的必要白名单。

识别格式、验证兼容、核对包摘要、信任发布者、授权使用是不同步骤。
包自带公钥只能说明自洽，不能把陌生发布者变成可信；同源 checksum 也不够。
新来源、新密钥或增加能力需要一次清晰的信任决定，不逐步骤反复审批。
公开发行默认匿名下载；私有源凭据由使用者显式提供，不要求开发者/私库身份。

下载器必须限制 HTTPS、重定向次数、总时限和元数据/包体大小，
防止非公开地址访问、DNS/重定向绕过及跨来源转发凭据。
解压必须拒绝路径穿越、链接逃逸、重复覆盖和覆盖已安装版本。
验证、信任及兼容检查完成前不执行包代码、安装脚本或能力探测 hook。
这些保护约束通用安装器，不等于只允许官方域名。

## 5. 使用公共 API，不再造业务授权层

受信任且启用的模块默认可以访问全部**公开产品 API**。
“公开”是已发布的产品契约，不是无需认证的公网入口。
模块和 Web/MCP 遵守同一现有认证、参数校验、确认、busy 和 unknown 规则；
不增加 `hostAccess`、`hostGrant`、每模块 API 白名单或逐步授权代理。
模块自己的业务权限、身份签发和绑定条件仍由模块负责。
本协议不是恶意代码沙箱，同用户模块进程通常拥有该用户的操作能力。

原 `POST /upload`、`/uploads/...`、`files/*` 和 `{kind,name,url,size,mime}`
是 Cockpit 自有托管契约，不是 Copilot 原生附件格式。它们及原 **25 MiB**
文件服务限制已随实现停放，不是当前薄本体提供的服务；旧文件数据未删除。

下一版由文件模块提供自己的 HTTP 上传/下载、托管和引用解析，本体不再把
`/upload` 或文件库作为模块的必要宿主服务。字节无需经过 JSONL 或 `host.invoke`。
模块自己验证文件来源、保存和读权限，并把可用文件转换为原生附件参数；
本体只适配所支持的 SDK 原生输入，不理解模块文件 ID、URL、数据库或存储策略。
原生 `MessageOptions.attachments` 在 SDK 1.0.13 中声明了
`file / directory / selection / blob`，并不提供浏览器托管文件库。
薄本体 HTTP/MCP 已镜像这四类原生参数，不含托管 URL 解析。
声明和转发参数不等于实证所有媒体格式都可被各运行时/模型解释。
文件路径必须能被 Copilot 运行进程访问；异机模块自行解决传输，不能把
另一台机器的路径假报为可用。鉴权、输入校验、有限资源和未知结果保护不能退化。

创建只走 `session/new(cwd)`，拿到实际原生 ID 后才可以由使用者显式请求模块应用，
随后独立 `prompt`。不预留虚拟会话，不隐式创建替代身份，不自动发送欢迎/问卷。
删除只走原生确认和 busy 保护，不因模块解绑失败或模块离线而阻断删除。
外部应用只能将权威“对象不存在”视为失效；unloaded、超时和权限失败不是不存在。

### 5.1 前端也是插件，不预置业务槽位

宿主不预知文件、语音或其他模块需要的槽位；没有模块时，不放置专用空占位。
已有原生界面通过公开且有版本的组件身份和交互接口参与运行时组合。
插件可相对一个现存公开组件插入或装饰自己的视图，宿主只理解通用组合关系，
不根据官方模块名选择位置。目标不存在或版本不兼容时明确拒绝，不猜测替代目标。
无预置槽位不等于无协作契约；把 CSS 选择器、私有组件实现或整个内部 store
当成接口，不满足这个要求。

```text
无插件：         输入框 -> 发送按钮
文件插件加入：   文件按钮 -> 输入框 -> 发送按钮
语音插件加入：   文件按钮 -> 输入框 -> 麦克风按钮 -> 发送按钮
文件插件另贡献： 输入区下方的暂存文件视图
```

以下只说明组合语义，不确定首版 wire schema、函数名或实际组件 ID：

```ts
ui.insert({
  target: 'native-chat.message-editor',
  position: 'before',
  component: FilePickerButton,
});
```

模块前端应以插件入口注册贡献，而不是自行启动另一个完整 SPA 并接管根节点。
可信发行包绑定前端 JS/CSS/资源和后端入口的固定版本与摘要；
动态加载发生在信任、启用和兼容检查之后。独立编译不等于任意构建产物都能融合。
当前 React 技术栈的最薄候选是共享兼容的 React 运行时、基础控件和主题变量，
模块业务单独打包；具体依赖版本/加载 ABI 仍需实现时确定。
ES Modules 或 Module Federation 只解决加载/依赖问题，不替代 UI 协作契约。

宿主管布局、焦点、无障碍、移动端收纳和稳定组件身份；加入插件不能重建原输入框
而丢失输入状态。多个贡献的顺序、重复 ID、同目标替换冲突和卸载必须有确定规则，
不能依赖下载完成顺序或模块私自改 DOM。可信同页代码不是恶意插件沙箱；
渲染错误边界能处理普通故障，不能宣传隔离任意同权限代码。

输入协作围绕原会话/草稿身份、编辑版本和一次提交快照：
文件模块提供已就绪的原生附件，语音模块编辑文字，粘贴/拖拽须防止重复消费。
本体统一收集就绪贡献并发送一次，不让多个模块抢发送权、生成隐藏消息或新队列。
原生受理后只清理该次贡献；晚结果不得写入另一会话或覆盖后来输入。
尚未就绪的贡献必须可见且可由用户移除，不能静默丢弃后发送。
卸载释放该插件的节点、订阅和采音等资源；未知发送不重放。
浏览器文件选择/麦克风权限需要由已加载的前端响应真实用户手势，
不能用一轮后台 HTTP 往返模拟。UI 协作接口不是新的 `hostAccess/hostGrant`。

### 5.2 文件在聊天流中的展示归文件插件

“聊天流展示”指消息区域内的文件 UI，不是把原生事件传输、消息身份、
主子 agent 归属、cursor、历史分页或重连交给文件插件。
这些仍由本体的原生适配及共享前端事件窗口统一负责。

文件插件使用该窗口的只读消息/事件数据及公开展示组合契约，贡献文件卡片、
图片/视频预览和下载控件。文件元数据与原件按需向模块自己的后端读取。
模块自有标记/URL 的识别和解析也归模块；不能在本体残留特殊 `/uploads`、
文件模块 ID 或附件卡片分支来“帮助插件渲染”。
注册依据公开展示对象/规则，不预埋文件专用消息槽位，也不把所有普通文本
交给文件插件作为聊天可用的前提。

文件展示必须覆盖历史加载、实时新增/替换、子 agent、重连补页以及插件
启用/停用后的当前窗口。复用同一窗口，不为渲染额外订阅另一条原生历史流、
复制整份会话或全历史扫描；不修改原生事件和 cursor 来实现展示。
展示贡献及异步文件读取绑定原消息/版本，不能错配到后来复用的视图。

没有匹配插件或插件失败时，本体保留原始消息文字、引用及适用的通用未支持
展示提示，不伪造预览、不启动模块兜底、不删除文件或原生消息。
模块下载/预览不可用须如实表达；普通原生文本聊天、队列和会话操作仍可用。
旧托管链接和既有数据的迁移/访问规则需要单独设计，不能靠删除记录、
修改原生历史或永久保留宿主文件业务兼容层解决。

## 6. 后续生命周期的最小语义

```text
URL -> inspect -> verify -> install -> configure? -> start? -> apply?
         |          |                      |            |
       不识别     缺信任/不兼容           缺配置      未运行/未应用
       明确拒绝   清楚停下               清楚停下   不能假报成功
```

一键操作可以串联已满足条件的步骤，但不能把“安装完成”当成服务运行或会话接入。
没有 service 的模块跳过 start，而不是以假服务健康结果补齐流程。
安装版本、默认选择版本、共享服务实际版本和 session 已应用版本分开表达。
冷恢复应恢复原 pins；显式更新不能暗中升级已有会话或重做业务初始化。
没有这套恢复实现前，不重新开放本体模块加载入口。

有副作用的操作至少绑定稳定 `operationId`、目标身份和输入摘要。
回执示例是**未来语义示例，不是已注册接口**：

```json
{
  "operationId": "example-install-001",
  "moduleId": "org.example.notes",
  "version": "1.0.0",
  "state": "accepted",
  "effect": "not-confirmed"
}
```

结果至少区分 `accepted / succeeded / failed / unknown`；存在等待原因时说明原因。
同 ID、同输入只能读取原结果；同 ID 不同输入冲突。超时不重发，不用新 ID
掩盖未知结果。副作用已完成后清理失败不能反转已完成效果；恢复保留原身份与证据。
同目标变更需串行/条件写保护，原生忙碌与同名能力冲突必须先拒绝。

升级/回退必须考虑配置和数据兼容：可备份配置，不回滚业务数据；
不兼容时明确停下。卸载默认保留配置、数据、秘密和历史，只解除实际使用及运行资源。
启停失败不得伪报已退出，也不能杀未知进程。未来实现的清理规则不授权清理当前旧数据。

## 7. 后续接入的验收门槛

先实现一个使用必要最小能力的合成模块，再逐个接入真实模块。
使用已实现能力的新 `moduleId`，仅给合规链接就必须能完成发现、验证、安装并使用，
不得改宿主枚举、路由表、if 分支或让开发者手工拷包。出现真正的新能力类别时，
可以显式演进协议和通用宿主，但不能伪装成已经支持。

前端插件还必须在本体无需重新编译、无业务槽位预置的情况下，与已有公开组件
共同形成统一界面。文件插件验收须包含输入区、文件库和聊天流展示的完整闭环，
并覆盖无插件、禁用、加载失败、组件不兼容和异步结果过期；不能只演示菜单页
或按钮出现。真实原生附件使用与模块文件下载分别验证，不以静态示意自证。

原角色内容回到内容模块；原任务身份、调度及网关回到任务模块；
原渠道绑定、收发、媒体和业务恢复回到渠道模块。各仓的业务适配不在本轮实施。
安装器、信任校验、公共 API、原生适配和本体最小恢复属于不可依赖待安装模块的宿主基础。
文件、通知/收件箱、语音按 2.1 节归属独立能力模块；其他自有能力的具体归组
按[完整模块清单](module-catalog.md)界定，不按按钮机械拆分。
当前实施范围是保留原始源码并从本体拆出，不是把这些目录写成可运行模块，
也不包含部署或数据迁移；固定源码基线的独立审阅范围保持不变。

旧接口盘点和较大候选设计可从
[清理前的固定文档](https://github.com/waksana/cockpit/blob/33696b81c5d2ebe073e4700410c1cc4adabc4c1b/docs/module-contract-draft.md)
追溯；不是当前实现、后续兼容承诺或新的执行授权。
