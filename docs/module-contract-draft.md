# 基础模块协议：同进程、冷加载设计

> **目标设计，尚未实现。** 当前源码没有模块加载器、模块 HTTP MCP 端点或下次启动消息模块。
> 2026-09-13 19:34–20:49 的最终决议是：一个前后端服务包；模块同进程 import、
> 随宿主关闭；首版不热加载；MCP 同端口不同 path；graceful 退出属于本体。
> 不再沿用独立模块服务/运行器或“模块负责本体安全关闭”的方案。

产品要求以 [R1–R8](product-requirements.md#single-service-target) 为准。
本文唯一维护未来模块接入契约；[模块目录](module-catalog.md)维护能力归属，
[架构](cockpit-plan.md)维护当前事实，[部署记录](deployments.md)记录已发生的上线。

## 1. 一个宿主，不是多个部署单元

```text
Cockpit 前后端包
└─ 一个直接启动的宿主服务
   ├─ HTTP/API、built Web、原生 SDK 适配
   ├─ import 已选择模块 A 的后端
   ├─ import 已选择模块 B 的后端
   └─ 同端口提供各模块的前端资源、API 与独立 MCP path
```

模块包可以同时含前端、后端、角色说明、skill 和其他资源，不强制每种能力都出现。
有后端的模块必须能作为库被宿主进程 import；纯内容/前端模块不需要伪造后台入口。
模块不自行 `listen`、启动常驻守护进程、保活、重启本体或选择本体发行版本。
独立仓库、独立版本、配置和业务数据继续成立；独立仓库不等于独立服务进程。
Task/微信此前的独立进程实现需要另行适配，不能把现有服务包直接当成合规模块。

这里约束的是 Cockpit 与模块的运行责任，不要求 SDK、原生 MCP/工具或浏览器
全部合并成一个 OS 进程。同进程模块共享内存与崩溃边界，不是隔离恶意代码的沙箱。

主程序 runner、私有 launch、循环 start wrapper、consumer 自更新、私有部署审批/回执和回滚
不属于此模块宿主。普通构建、测试、产包可以留在开发仓库。
**主程序自更新器与通用模块包接入不是同一能力**：移出前者，不取消后者的签名、
兼容检查和安装选择。

## 2. 最小声明与可选能力

模块是稳定身份、版本和职责明确的代码/内容包，不按按钮数量机械拆分。
业务身份签发、唯一绑定、业务数据和秘密由模块负责，不能接管原生 session、
history、模型上下文、队列或调度权威。

| 必选约定 | 含义 |
| --- | --- |
| 身份、版本、格式与摘要 | `moduleId` 是稳定字符串，不是官方枚举；显示名不是身份或信任证明。 |
| 静态能力声明 | 至少声明一个受支持能力，安装前可读；不执行代码来猜包里有什么。 |
| 兼容与路径约束 | 声明真正需要的宿主/SDK/平台条件；包内路径不逃逸，不把未知当兼容。 |
| 程序与数据分离 | 版本目录不可变，配置/秘密/业务记录不写入代码包；卸载默认保留数据。 |
| 明确的运行结果 | 安装、选中、实际加载、会话使用及失败/未知分别报告，不用统一“成功”掩盖差异。 |

| 可选能力 | 目标边界 |
| --- | --- |
| 角色说明、skill | 显式应用内容，不替代工作区规则、不隐藏发送初始化消息；后续正文和引用读取属于一致版本。 |
| 后端入口 | import 后向宿主注册能力和必要资源，随宿主关闭释放；不拥有独立服务生命周期。 |
| MCP | 在自己所属 path 提供工具、资源、prompts 和协议连接，不混入其他模块的工具表。 |
| 命名空间 API | 由宿主通用机制注册并 serve；模块定义业务 schema，不在宿主写逐模块 if。 |
| 前端插件 | 同包内的 JS/CSS/资源，贡献页面、控件与展示，依赖公开的 UI/草稿契约。 |
| 配置与会话应用 | 模块自有 schema、配置版本和秘密引用；实际原生 ID 建立后才可显式应用。 |

以下仍只是**候选字段示例，不是可安装 wire schema**：

```json
{
  "schemaVersion": 2,
  "kind": "cockpit.module",
  "moduleId": "org.example.notes",
  "version": "1.0.0",
  "name": "Notes",
  "requires": { "hostProtocol": 2 },
  "capabilities": {
    "roles": [{
      "id": "reader",
      "instructions": "roles/reader.md",
      "skills": ["skills/notes"]
    }]
  }
}
```

具体字段、import 导出形状、组件 ID 和 ABI 要随首个真实能力落地。
数字 `2` 不代表已有宿主 v2，更不等于现存 consumer 安装协议的版本。
无后端的内容包不必声明后台入口；有后端时需声明入口和实际运行依赖。
同名冲突不能用覆盖、改显示名或隐藏兼容层解决。

## 3. URL 入口与信任

基础方向仍是合规的 **HTTPS 签名发行描述 URL**，绑定身份、版本、manifest、
包 URL、大小、摘要、有效期与发行序列。签名覆盖明确编码的 payload 字节；
发布者公钥必须来自独立信任或用户对新来源的明确确认。
Ed25519 envelope 是候选编码，不因文档存在而成为可调用安装 API。

普通 HTML 仓库页、裸 ZIP、未签名 manifest 不猜测为可安装模块。
包自带公钥或同源 checksum 只能自洽，不能替代发布者信任。
推荐目录可替换，不能变成官方 moduleId、仓库或域名白名单。
公开发行默认匿名读取；私有源使用消费者自己的下载凭据，不依赖开发者 CD 身份。

必须保留 HTTPS、地址/DNS、重定向、时限/大小、跨来源凭据和解压逃逸保护。
验证、信任和兼容确认前不 import 包代码，不执行安装脚本或探测 hook。
增加能力或更换信任来源需要清晰的信任决定，但不增加逐步骤审批链。
首版不加入自动依赖安装、跨模块数据库、循环依赖或远程安装脚本。

## 4. 同端口、独立 MCP path

示意布局如下，**不是当前已开放的路由或固定 moduleId**：

```text
同一个宿主 :8771
/mcp/org.example.notes  -> Notes MCP
/mcp/org.example.files  -> Files MCP
```

客户端可将两个 URL 注册为不同的 HTTP MCP 配置项，分别连接、启用或禁用。
模块后端留在宿主进程，不为每个模块另起 stdio MCP 服务。
当前 `apps/mcp` 是到 Cockpit API 的 stdio 客户端，不能把它误报成已经实现上述 HTTP 宿主。

隔离必须落实在各自的工具/资源/prompt 注册和协议连接上；有状态 transport 的
MCP session ID 必须绑定自己的 path，不能跨模块复用。这是 MCP 协议会话，
不是另造 Copilot session。一个 path 的通知和关闭不广播到其他模块的连接。
不能几个 path 最终共用同一个包含所有模块工具的大 MCP 注册表。

path 隔离不是账号、权限、内存或故障隔离。已有认证、来源保护和用户授权适用于所有入口；
不引入 `hostAccess`、`hostGrant` 或模块 API 白名单。
受信任启用模块仍可调用全部公开产品 API，但不会因此得到外部 CD 的审批或 admin 凭据。
原生 MCP 配置/开关继续由 Copilot 管理，不暗中向所有 session 注入模块或保存其开关副本。

实现采用双方实际支持的 MCP 传输/版本。现有 MCP SDK 1.30.0 支持的协议版本止于
2025-11-25；不能因最新规范变化而假报现有客户端已兼容。
参考 [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#streamable-http)。
首版端点在宿主启动时注册，不为被延期的热加载建设动态路由替换系统。

## 5. 前后端共同组成一个 App

模块前后端及静态资源作为同一固定版本的包交付，由宿主统一提供访问。
前端导出插件注册入口，不启动独立 SPA 接管根节点；普通页面导航时的按需 JS import
是浏览器加载方式，不等于宿主运行中安装/替换模块。

宿主不预知文件、语音等专用槽位。插件相对已有、公开、有版本的组件插入或装饰，
不依赖私有 DOM/CSS 选择器、内部 store 或逐模块名字判断。
目标组件不存在或不兼容时明确拒绝，不猜替代位置。
共享兼容 React、基础控件和主题是最薄候选，具体 ABI 尚待实现；
把两个任意已编译 SPA 放在同一端口并不自动形成一个界面。

```text
无文件/语音模块： 输入框 -> 发送
启用文件模块：    文件操作 -> 输入框 -> 发送
再启用语音模块：  文件操作 -> 输入框 -> 语音操作 -> 发送
```

宿主维护布局、焦点、无障碍、移动端收纳和原草稿身份；贡献不能重建输入框丢失编辑。
顺序、重复身份和冲突有确定规则，不依赖下载完成顺序。
文件模块提供就绪的 SDK 原生附件，语音模块编辑文字；宿主发送一次，
不让模块抢发送权、创建隐藏消息或自己的投递队列。
ACK 只清本次提交的贡献，晚结果不覆盖新输入或另一 session；未就绪的贡献不可被静默丢弃。
文件/麦克风手势需由已加载前端响应，不通过后台调用伪造用户手势。

### 文件在聊天流中的展示

文件模块负责附件卡片、图片/视频预览、下载和自有标记/URL 解析。
不在本体留 `/uploads` 特判、文件模块 ID 或隐含文件渲染器。
它使用宿主当前的只读 all-agent 事件窗口，覆盖历史、实时替换、子 agent 和重连；
不另扫全历史、修改原生事件或另建会话库。

文件字节由模块自己的 HTTP 能力取得、存储并转换成
[SDK 原生附件](../apps/mcp/README.md#native-attachment-input)，不强制 JSONL/`host.invoke` 中转。
模块与宿主同进程不等于任意客户端路径都可读；浏览器/远程调用者的本地文件仍需实际传输。
无模块或加载失败时普通原生文本仍可读，但不伪造预览/下载或恢复已退役的文件服务。
旧数据访问规则由[模块目录](module-catalog.md#interim-behavior-and-adoption)维护。

## 6. 首版冷加载与 graceful 退出

```text
发现/验证模块包 -> 不可变安装与选择 -> 待重启生效
本体下次启动 -> 检查配置/兼容 -> import 选定模块 -> 注册 API/MCP/前端资源 -> serve
本体关闭 -> 等待已接纳工作收敛 -> 释放模块和 SDK/连接 -> 退出
```

首版不热加载、热卸载或运行中替换代码。新增、更新、停用或移除模块不会偷偷改变
当前已加载实例，必须明确显示实际版本和待下次启动的选择。
不能在当前进程仍使用旧代码时删除它的版本目录，或用“已安装”冒充“已生效”。
普通业务配置按模块明确 API 处理，不把修改配置自动等同模块代码已重载。
原生 session 的 MCP 开关仍可按原生规则使用，不是模块热启停。

宿主至少区分已安装包、下次启动选择、当前实际 import 版本、会话内容/连接的应用情况。
不再管理独立共享模块服务进程版本。角色/skill 新读取来自一致的已应用包及全部引用；
不能抹掉旧模型上下文来假装内容已刷新，也不能恢复原生临时开关镜像。
既有浏览器/MCP 客户端仍可能持旧代码或定义；主机重启不是远端客户端热替换，
新连接/页面初始化才确认新版本，不将不兼容的新旧组件混用。

本体自身提供 graceful 退出，不依赖模块决定何时退出，也不负责退出后重拉。
退出应使用宿主统一公开 API；其具体名称和受理/等待 schema 尚待实现，
当前 `/admin/restart` 的部署/consumer 语义不能被文档视为已经替换。
收口新独立工作，但允许已接纳队列和已有问答完成；根据新鲜原生活动及宿主在途资源
确认安全，再关闭空闲 handle。读取未知不能当 idle，不能等“所有保存会话被删除”。
模块初始化和资源释放从属于本体，不形成独立保活/排空/重启状态机；
模块后台工作必须归宿主管理，不能绕过关闭入口继续制造新原生工作。
原生会话删除不以模块业务解绑或回调为前置条件。

有副作用的安装/配置/应用操作需保留稳定身份、明确等待/失败/unknown 和原输入。
同身份冲突拒绝，未知不换 ID 重发；不兼容配置需明确停下，不回滚业务数据。
卸载默认保留配置、秘密、业务记录和历史。具体 API 名字/回执 schema 尚未发布。

## 7. 可选的下次启动消息模块

它不主持安全关闭，不确保进程重新启动，也不管理部署版本。它可以提供独立 MCP 工具，
记录用户显式请求的下一次启动消息，并可在记录落盘后调用本体的 graceful 退出。
MCP 返回受理后必须让发起的原生回合结束，不能等待自己退出。

```text
保存记录 -> 可选地请求本体退出 -> 返回
外部重新启动本体 -> 宿主/SDK/API 就绪 -> 模块处理旧实例留下的记录
```

记录至少区分原操作 ID、目标原生 session、prompt、创建时的宿主实例和发送状态；
状态保存在模块数据中，不是本体部署账本或原生会话镜像。
只处理面向下一次启动的记录，不因网页刷新或模块页面重新挂载再次发送。
目标不存在时明确失败，不自动创建替代 session；待发记录应能显式查询/取消。
精确字段和工具名仍待实现。

发送不能只用“发送后写一个 sent 布尔值”：

```text
pending -> dispatching -> accepted
                \-----> unknown
```

先持久化 `dispatching`，再调用普通 prompt；明确受理后写 `accepted`。
再次启动遇到未完成的 `dispatching`，按未知处理，不自动重发或谎称已发送。
当前原生 prompt 接口没有用于此用途的接收端幂等键，不能仅靠本地记录保证崩溃下不漏不重。
`accepted` 只代表受理/排队，不是目标完成、旧模型回合无损恢复或业务操作可以重放。

**当前事实不同**：已记录部署后的消息由外部 runner 的 `notify()` 根据提交者绑定的
session 发送，发送前记录 attempted；并非本体每次启动的隐式 prompt。
它在部署请求终态（包括非成功结果）通知，不等于上述可选模块已经存在。

## 8. 后续接入的验收边界

使用未预置 ID 的合规包，发现、验证、安装、冷启动加载后可以实际使用，
不修改宿主业务枚举、白名单或逐模块路由代码。没有后台/页面的模块不启动空服务。
安装成功但待重启时明确未生效；不同模块 path 的 MCP 工具和协议状态不串用。

前后端共同使用包版本，界面组合无专用槽位，文件模块覆盖输入区、文件库和聊天流，
并验证不存在、禁用、加载失败、兼容冲突和晚结果。不能用静态按钮或手工拷包代替接入。
无需重新编译本体不等于无需重启；首版明确采用冷加载。

单包直启、同进程模块、分 path MCP、下次启动消息均是目标。当前迁出原件不是实现。
模块仓库适配、现行主程序启动链替换与上线另需实施和授权；文档不触碰真实安装、
凭据、业务记录或 native home。此前更大的独立服务设计仅可从
[固定旧文档](https://github.com/waksana/cockpit/blob/0f09124e0cc1efb4643277f2a84ab1380339fd4f/docs/module-contract-draft.md)
追溯，不作为继续实现依据。
