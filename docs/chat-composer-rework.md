# Chat 输入区：CSS 优先的轻薄底栏

> 历史组件返工记录，不是本轮薄本体的完整功能清单。文件、语音和富草稿已
> 停放；普通文字布局、原生决策及滚动保护保留。当前范围见[模块目录](module-catalog.md)。

当前实现恢复连续的满宽底栏，而不是把整个输入区包进悬浮卡片。
主要验收对象是输入区整体的厚度、比例和自然贴底，不是按钮的单点几何。
本轮为源码与隔离组件交付，**不包含生产部署或真实 iPhone 验收声明**。

## 布局与交互

- 满宽 `.chat-input` 无外框、无外圆角、无上下 margin。
  内容保持与阅读列对齐，底栏背景自然延伸到底部。
- 单行文字区和图标按钮为 40px 高，底栏上下各 4px：
  未计设备安全区时，普通消息、问答和计划的空输入均为 48px。
- 安全区继续使用浏览器 `env(safe-area-inset-bottom)`，放在底栏内部 padding，
  不全局删除、不假定键盘高度、不使用负 margin。
  出现既有本地错误托盘时，由最底部托盘保留安全区，输入栏不再重复计入。
- 只有文字区有轻量填色，没有“外卡片再套内部输入框”。
  输入聚焦仅略加强填色，不加粗内框；其他按钮/链接的键盘焦点仍可辨。
- 问答占位为“输入回答…”，计划为“输入新指令…”。
  原卡片仍完整显示问题、选项及新指令说明，避免把重复的长说明塞进 placeholder，
  让空输入被撑成两行。“仅选项”请求仍不能用自由文本发送。
- 实际长草稿仍使用原 CSS `field-sizing:content` 自然增长、到上限后内部滚动，
  不固定为单行或裁掉文本。上限用 CSS `dvh` 及既有错误托盘高度计算，
  不新增监听器；旋转、短窗口及多种控件组合仍可编辑和操作。
- 发送、附件和语音统一为 22px 居中图标、40px 圆形触控范围与透明底色。
  发送不再有显大的实心圆底，可发送时仅以强调色区分；不加厚输入区。
  pending、禁用、附件暂存、ACK 和晚结果保护均保留。

用户自己消息的时间与复制操作在气泡外的同一行，整行位于气泡下方 2px，
右边缘随所属气泡对齐，短气泡不为复制按钮被拉宽。
保留 v3 的同一消息容器、原时间格式、消息 ID 和历史锚点；
保留问答附件协议和原生生命周期。
发送图标使用向上箭头，提交中仍显示原提交状态；不改变发送/排队语义。
工具、思考和 skill 使用同一紧凑活动行，收起时只有一行，超长标题省略。
思考和工具按所属助手消息收纳为独立过程摘要，消息间用细线分隔，不跨消息合并。
历史过程默认收起，当前流式消息初次挂载时展开；之后更新或结束不覆盖用户的展开选择。
摘要仅展示本消息已加载的工具数量、是否含思考、明确状态以及原消息时间，
不计算耗时、不生成总结、不额外读取历史。失败优先显示在摘要中，完整状态由可访问名称说明。
正常完成工具不再重复显示“已完成”，读屏仍能读到；其它状态文字保留。
工具与思考通过右侧展开按钮查看详情；工具展开后在原标题位置显示完整标题，
参数与输出接在同一容器下方，不另开一个游离的引用框或重复打印标题。
原生工具名与标题相同时不重复显示；不同的工具名、实际参数、输出及错误仍保留。
尚无参数/输出的记录明确说明。skill 只显示单行名称，不提供详情或伪装成按钮。
流式思考仍保留原来的默认展开和结束收起规则，用户手动选择不被覆盖。
没有正式正文或附件时，不渲染正文和复制占位；纯空白文本同样不产生空正文。
有内容的消息使用淡色纯文字复制，贴近正文右下方，24px 操作高度，不带图标或大工具栏。
复制内容不作裁剪，成功、失败及键盘焦点反馈保留；代码和工具参数的复制仍沿用原样式。
本轮组件场景可在开发 lab 的 `process-history` 查看；已部署的旧 review 基线不随源码更新。

当前执行状态、停止与“打断并继续”统一放在输入栏上方的执行控制区，
顺序为状态与并列操作、操作说明/结果、排队消息。停止不再藏在可滚动的消息末尾，
打断按钮也不再单独属于队列列表。按钮仍沿用原可用条件和回调：
打断保留队列，停止显示是否清空队列；空闲队列不冒充运行中，纯只读视图不显示操作。

## 从原版到 v4 的对照

在同一 Chrome、390×844 CSS px、相同合成输入状态、设备安全区为 0 的条件下，
分别挂载各版本真实生产 Thread/Composer。原版只增加无后端连接的测试入口，
没有改其生产组件或样式。以下不是用户手机的运行测量。

| 输入状态 | 原版 `1a3c49c` | v3 `ea97912` | v4 CSS 底栏 |
| --- | --- | --- | --- |
| 普通空输入：底栏 + 上下外距 | 57.6px | 56px | 48px |
| 空问答/计划：底栏 + 上下外距 | 77.2px | 80px | 48px |
| textarea：普通 / 问答占位 | 41.6 / 61.2px | 40 / 64px | 40 / 40px |
| 底栏本体到页面底边 | 0 | 4px 外 margin，另加安全区 | 0 |
| 底部留白归属 | 内部 8px + safe | 外 margin 4px + safe，另有内 padding | 内部 4px + safe |
| 整体外框 | 无 | 1px 独立边框 | 无 |
| JS 视口控制 | 无 | 全局监听与根 CSS 变量 | 无 |

旧版长占位同样可能撑高输入，因此不能把每个问题都归给新增 safe-area
或一个 margin 值。v4 同时收敛容器结构和重复占位说明，恢复视觉上的连续底栏。

## 明确删除的复杂度

`ea97912` 的全局 VisualViewport 方案没有取得“原布局/CSS 无法满足”的实机必要性证据。
本轮直接删除，而不是换文件或改名保留：

- `visualViewport.ts`、`useVisualViewport.ts` 及其专属测试。
- Shell 上的 viewport/window resize/scroll 监听、合帧写入和清理逻辑。
- 根元素的高度、偏移、遮挡与剩余安全区 CSS 变量。
- lab 的合成 viewport source、输入表单和边界模拟。

Shell 回到原来的固定 `100dvh`，本地错误托盘使用既有 CSS 高度扣除。
没有新的键盘检测、机型推断、根样式写入或用户缩放控制。
已有 `ThreadScroll` 继续作为唯一消息滚动写入者，本轮未改其行为。

## 场景和证据边界

```sh
COCKPIT_CHAT_LAB=1 pnpm --filter @cockpit/web dev \
  --host 127.0.0.1 --port 47831 --strictPort
```

服务器本机打开 `/chat-lab.html?scene=ask&compact=1` 或
`scene=plan&compact=1`。顶部可展开合成场景控制；`user-time` 用于检查保留的外置时间。
旧的 `viewport=1` 合成几何入口已退役，不再用人为设定的 viewport 证明 JS 必要。
正常生产构建不包含 lab。临时预览由本轮 owner 启动并在收尾停止，不保活或 detach。

本轮定向覆盖 Chrome 的 320/390/1440px、普通/问答/计划空占位、长草稿、
禁用/可发送/pending、Tab 焦点、受理期间继续编辑、实际浏览器 resize/旋转与 pinch、
附件/队列/本地通知组合，以及保留的外置时间戳。
安全区使用 Chrome 原生 DevTools 的 inset 仿真独立检查，明确不是 iOS 实机。
原图含私人内容，仅在授权本机查看，未复制到公开 fixture、Git 或 CI/Release。

用户使用 iPhone 主屏 PWA 的事实已确认，无需反复询问。
没有实际设备连接或同机新旧 `visualViewport` 数据，因而不能说明截图中所有空白的
精确来源，也不能宣称 CSS 方案已经证明修好每个 iOS 版本的键盘动画。
系统“上一项/下一项/完成”工具条不是网页组件，既不会隐藏它，也不把它计作网页留白。
如果后续同机对照证明确有 CSS 不能解决的遮挡，应针对那个问题评估最小局部适配，
而不是默认恢复整套全局控制器。

最终源码 SHA、集成结果、定向画面、CI 的实际结果及预览清理情况在交付回执中分别记录。
v3 的原生 smoke 清理失败是历史已知结果，不属于本轮 UI 范围，也不以重跑或改动原生
生命周期绕过它。
